# v2 再設計 — アーキテクチャ刷新の決定と移行計画

**状態: 決定(2026-07-03)**。本書は v1(現行 `Assets/VRCloth-Declipper/`)の到達点を初期値として、システムをゼロから設計し直した場合の目標アーキテクチャと、そこへの段階移行計画を定める。実装スケルトンは [`dotnet/`](../dotnet/README.md)。

## §1 動機 — v1 の3つの律速

v1 のアルゴリズム的到達点(変位場方式、メッシュSDF、projected ソルバ、プリフライト診断)は健全であり、作り直しの動機はアルゴリズムではない。律速は構造にある:

1. **テストループが Unity バッチモード律速** — Core は「エディタ非依存」だが `UnityEngine.Vector3` に依存するため、ユニットテストは Unity 2022.3 バッチモード必須(分単位、Unity がプロジェクトを開いていると実行不可)。幾何ソルバの探索・較正・測量(パラメータスイープ)の反復速度をこれが支配している
2. **体表現の二本立て** — カプセルとメッシュSDF の2バックエンドが `IBodyCollider` の下に並存するが、検出パスは二本のまま(カプセルはヒットにカプセル index を持ち、メッシュは持たない非対称が run log・可視化へ漏れている)
3. **プリミティブの狭さ** — 中核が「貫通修正(押し出し)」であるため、採寸(`GirthProfile`)・診断(プリフライト)・将来のポーズ対応が、それぞれ別の幾何基盤の上に積み増しになっている。ソルバも coarse `Solve` と `SolveProjected` の二本立て

## §2 目標アーキテクチャ — 4本柱

### 柱1: 純 .NET コア(UnityEngine 完全非依存)

- 幾何計算のすべて(SDF・検出・ソルバ・平滑化・束縛・診断・採寸)を `System.Numerics.Vector3` ベースの素の C# ライブラリ(`netstandard2.1` / C# 9 — Unity 2022.3 と互換な上限)に置く
- テストは `dotnet test` で秒単位。Unity バッチモードは「Unity 統合(キャプチャ・書き戻し・NDMF)」の検証だけに縮小する
- Unity 側は薄いアダプタ: メッシュ/ボーンの吸い上げ(`UnityEngine.Vector3` ⇄ `System.Numerics.Vector3` の変換)と書き戻しのみ
- 測量ファーストの探索(収束性・しきい値スイープ)もヘッドレスで回せるようになる

### 柱2: SDF 単一体表現

- 体の表現は**符号付き距離+勾配を一括で返す SDF が唯一**(`ISignedDistanceField.Sample` — v1 が距離と勾配を別クエリで二度引いていた非効率も解消)
- ボーンカプセルは「素体メッシュが取れないときの安価な SDF ビルダー」に格下げ(`CapsuleSetSdf`)。メッシュSDF(`MeshSdf`、v1 の BVH+Barnes–Hut 巻き数を移植)と完全に同じ経路を通る
- 検出・ソルブ・プリフライト・採寸が単一パス。カプセル index のような表現固有情報は、診断用メタデータとして SDF 実装が任意に付与する(コアの契約には含めない)

### 柱3: ソルバの一本化 — 制約付き最適化

v1 の二本立て(coarse `Solve` / `SolveProjected`)は後者が正解に収束した歴史なので、最初から

> minimize 変位場の Laplacian エネルギー s.t. SDF(x) ≥ margin

の射影付き反復(projected Gauss–Seidel 相当)一本で定式化する。λ・パス数・反復数のチューニングループは定式化に吸収され、「常に押しで終わる(最終状態は margin 面以上)」は不変条件になる。SDF サンプリングと平滑化は頂点並列可能なので、Unity 統合時に Burst/Jobs 化してライブプレビューをインタラクティブにする余地を最初から確保する(コアは配列指向で書く)。

### 柱4: 体表面対応(binding)を中核プリミティブに

最下層のプリミティブを「貫通修正」でなく「**布頂点 = 体表面上の最近傍点 + 法線方向オフセット**」という束縛(`SurfaceBinding` / `IBodySurface`)に据える。すると:

- **貫通修正** = オフセットが margin 未満の頂点をクランプする自明ケース(+柱3の平滑化)
- **代表ポーズ対応・リターゲット級の変形** = ソース体で `Bind`、ターゲット体(またはポーズ変形後の体)で `Evaluate` する再評価
- **採寸・プリフライト・クリアランス統計** = 束縛の統計(オフセット分布、対応の歪み)そのもの

**製品スコープは不変**: 「貫通修正に特化、リターゲティングは先行ツールの領分」(ROADMAP 基本理念)はそのまま。束縛はあくまで**内部基盤**であり、採寸・診断・修正・ポーズ対応が同じ基盤に乗ることが目的。リターゲットの製品化は別判断(現状は判断しない)。

## §3 維持するもの(v1 の正解)

- **変位場方式** — 元頂点は不変、original + displacement で合成。布ディテールが生き、Undo 系も単純
- **NDMF ファースト** — ビルドパスが正、エディタプレビューは同一コアの派生(「編集時=ビルド時」の構造的保証)
- **宣言的コンポーネント** — Runtime は設定の入れ物のみ(`IEditorOnly`)
- **プリフライトの誠実性** — RED 原因の名指し(`RedCause`)、false-green ガード、診断の構造化データ化([DIAGNOSTIC_HONESTY.md](DIAGNOSTIC_HONESTY.md))
- **No Cache 原則** — 素体形状を復元しうる中間データを保存・出力しない。純 .NET 化してもこの規律は変わらない(コアはメモリ内で完結、永続化 API を持たない)

## §4 移行段階

| 段階 | 内容 | 状態 |
|---|---|---|
| **S0** | スケルトン — `dotnet/` に純 .NET コアの契約(インターフェース・型・アルゴリズム仕様の XML doc)と最小テストを配置 | landed(2026-07-03、本書と同時) |
| **S1** | 幾何コアの移植 — v1 Core の数学(カプセル SDF・MeshSdf の BVH+巻き数・検出・平滑化・projected ソルバ・プリフライト)を `dotnet/` へ移植。**ゴールデンテスト必須**: 同一入力に対し v1(Unity)と v2(.NET)が同一出力を返すことを、v1 から吐いた固定フィクスチャで固定してから置換する。フィクスチャの入力は合成メッシュか再配布自由な基準マネキン(ROADMAP フェーズ5)に限る — 購入アセット由来の頂点データは public リポジトリにコミットできない(No Cache 原則) | 未着手 |
| **S2** | Unity アダプタ — 同一ソースを Unity にも食わせる(方式は csproj の source-share か UPM ローカルパッケージ、S2 冒頭で決定)。既存 Editor 層の呼び出しを段階的に v2 コアへ差し替え | 未着手 |
| **S3** | 二重経路の削除 — coarse `Solve`、カプセル専用検出パス、`IBodyCollider` の旧契約を削除。EditMode テストは Unity 統合(キャプチャ・書き戻し・NDMF・実スキニング整合)だけに縮小 | 未着手 |

移行中の不変条件: **各段階の終わりで v1 パイプラインは常に動作する**(ビッグバン置換はしない)。ゴールデンテストが通るまで v1 コードは削除しない。
